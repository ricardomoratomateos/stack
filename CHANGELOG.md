# Changelog

All notable changes to Stack are documented here. The format is based on
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project
adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Changed

- **A redesigned Review panel.** It wears your theme's own diff colours (added, removed, and the words that changed inside a line), with quiet hunk headers, a sticky header per file with a status pill and `+N −M`, and **Viewed** / collapse per file (remembered). The file list is a folder tree (single-child chains folded: `agent/src/brain`) with full names, a filter, comment badges and the current file highlighted as you scroll. Long lines scroll sideways per file with the line numbers pinned, or wrap with the **Wrap** toggle. Keyboard: `j`/`k` files, `n`/`p` changes, `c` comments on the line under the pointer, `Cmd+Enter` adds a comment (or sends them), `/` filters, `?` lists them. The accent follows `stack.sidebarStyle`, live. Large diffs stay quick: files are built only near the viewport, and generated or very large files start collapsed behind a "Show diff" button.
  - The prompt sent to the agent now says whether a line number is from the old file or the new one, and names the old path of a renamed file.
  - A refresh button re-reads the diff, and switching between branch and working tree keeps the comments whose line is still in the diff instead of dropping them all.

### Added

- **Manager agent (MCP).** Stack is now an MCP server, so a Claude Code session — the VS Code panel with your Jira and Slack servers, say — can turn tickets into tasks and run them: `stack_status`, `stack_create_task` (idempotent per ticket, branch `<KEY>-<slug>`, the ticket's text handed to the worker as data), `stack_send_to_agent`, `stack_read_agent`, `stack_wait` (event-driven, up to 110 s), `stack_env` and `stack_request_review`. **Stack: Enable Manager (MCP)** registers it with Claude Code (user scope); **Stack: Disable Manager (MCP)** removes it. Claude and Codex agents Stack starts get it for their own task, beside your own servers. Each window answers on 127.0.0.1 with a per-window token from a 0600 discovery file the server reads by itself; requests from browsers are refused. A task created from a ticket shows the key as a small chip next to its name (all three sidebar styles), and an agent that asks for review moves to *Ready for review* with its summary as the row's line.
- **A terminal tab per session.** An agent and a shell of the same worktree no longer take turns in one terminal: each session opens in its own tab (`<worktree> · <session>`), which you can drag into another editor group, resize and reorder like any editor. Clicking a session's row brings its tab forward, **Stack: Open Session to the Side** moves the focused one beside the active group, killing a session closes its tab, and a dropped screenshot or `Cmd+Alt+V` goes to the session whose tab it landed in. `"stack.sessionTabs": "single"` keeps the one-terminal-per-worktree layout.
- **Three sidebar styles**, switchable live with `stack.sidebarStyle`, **Stack: Switch Sidebar Style** or the settings panel: `aside` (monochrome, one lime accent), `claude` (terracotta, worktrees grouped by what they need from you) and `mission` (state counters that filter, an attention queue, cards with a metadata grid). All three show the same things and offer the same actions; worktrees are grouped as needs you / ready for review / working / idle / missing, with the diff size, the age in that state, and the agent's own question when it asks for permission.
- **A worktree whose folder is gone** now shows under "Missing" with a **Forget** button, instead of silently vanishing.
- **Docker state on the sidebar**: the stack's start/stop is disabled while Stack is working on it, a failed start shows compose's error on the worktree, and a docker daemon that is down says so in the health strip instead of looking like an empty stack.
- **The window is named after the project**: "aside (Workspace)" instead of "Untitled (Workspace)". When the first worktree folder (or the main folder's branch label) turns a single-folder window into a workspace, Stack writes a `<repo>.code-workspace` into the repository's `.git/stack/` (inside the trusted repo, so the window does not open in Restricted Mode, and invisible to git) and opens that — the same single restart as before, no extra reload. The file holds the folders Stack adds (main first, then the worktrees) and your workspace-level `stack.*` settings; the window's Stack state (selected worktree and the like) comes along, and agents re-attach from tmux. A window that is already "Untitled (Workspace)" is asked once per repository (**Name it** / **Not now**, remembered); **Stack: Name This Workspace** does it any time. Reopening the folder later goes back to the same file. If the file cannot be written, Stack does what it did before and says why in the Stack output.
- **Stack: Focus Next Worktree Needing Attention** (`Cmd+Alt+J`) walks the attention queue, longest-waiting first, and lands where the work is: the terminal of an agent that is asking, the Review panel of one that has finished.

### Fixed

- After a reload, a worktree could take over another's terminal when its name was a prefix of the other's (`feat` and `feat-login`). Terminals are now matched by the tmux session they are attached to.
- The review panel's confirmation no longer says "Sent to the running agent" when that agent had exited and the comments launched a new one.
- **A syntax error in `~/.claude/settings.json` or `~/.codex/hooks.json` no longer costs you the file.** It used to "start fresh" and write back only its own hooks; it now leaves the file untouched and says where the error is. Writes are atomic, follow symlinks, keep the file's permissions, and the first change keeps your original as `<file>.stack-backup`.
- **Several VS Code windows at once.** Each agent now reports to the window showing its worktree, instead of every event going to whichever window opened last. Closing a window no longer removes the hooks from under the others, and agents keep reporting across a window reload — opencode included.
- Search and Quick Open finding nothing, and the whole explorer dimmed, after selecting a worktree in another window or deleting the selected one. The selection is now per window.
- Saved tabs and stashed breakpoints of one window being overwritten by another.
- Two windows creating a worktree at the same moment being given the same port slot.
- **A repository that versions `.vscode/` keeps a clean worktree.** Creating a worktree overwrote its checked-out `launch.json` and `settings.json`, so it started dirty — in the review diff, the `+N −M`, and the agent's next commit. Stack now only writes the files the checkout does not have, never re-points a versioned `launch.json` at a new port, and leaves a versioned `settings.json` out of search scoping (VS Code keeps per-folder settings nowhere else, so that folder stays searchable). The generated `settings.json` only excludes `node_modules` when there is a `package.json` and `vendor`/intelephense when there is a `composer.json`; with neither, none is written.
- **The PR badge tells the truth.** A merged or closed PR used to vanish from the sidebar (only open PRs were asked for); it now shows as merged or closed. The badge opens the PR on GitHub, carries a dot for its checks (green passed, red failed, amber running), says "draft" for a draft and marks requested changes. An open PR is checked every minute, anything else every five.
- **The Glass chime only rings when it has something to say.** It played on every agent stop — including the agent you were watching finish, and with `stack.notifyOnAttention` off. It now comes with the native notification and nowhere else: when that setting is on, VS Code is in the background, and the stop is news.
- **The agent waits for the setup script.** It used to start 300 ms after the script was typed into a terminal, so in a PHP or Node repository it woke up without `vendor/`, `node_modules/` or `.env`. The setup now runs in the background (output in the **Stack** output channel, 30-minute limit) and the agent starts when it succeeds. The row reads "Preparing… 1:42" meanwhile; a failure stays on the row with icon buttons to show the log, retry, or launch the agent anyway, and a toast. **Init worktree** re-runs the setup the same way. `stack.setupInTerminal` (also in `.stack/config.json` and the settings panel) keeps the old terminal behaviour for scripts that ask questions.
- **Deleting a worktree says what it would throw away.** The confirm used to say nothing over a `git worktree remove --force` and a `git branch -D`. It now lists uncommitted changes, commits not pushed, commits not in the base and the PR's state, and the branch option counts what it discards ("Delete + branch (discards 3 commits)") — the unpushed commits, or, for a branch never pushed, everything it added over its base. A worktree whose PR is merged and that has nothing uncommitted or unpushed gets **Clean up** (worktree and branch) as the primary button.
- **Ages survive a reload.** "Waiting 3h" went back to "now" every time the window reloaded, and the attention queue reshuffled with it. When each worktree entered its state is now kept per window, and the half-loaded first moments after a reload no longer overwrite it.
- **An idle agent is not asking for anything.** Claude's `Notification` hook also fires when a finished agent has sat at its prompt for a minute ("Claude is waiting for your input"), and Stack read every notification as a permission request — moving the worktree from ready for review to needs you. Notifications are now read by their `notification_type` (or, from older agents, their text): permission prompts need you, idle reminders leave the agent ready, anything else changes nothing.

## [0.1.0] — 2026-08-30

First release.

### Added

- **Worktree manager** in the sidebar — create, rename, and delete git worktrees, branching off a configurable base (`stack.defaultBaseBranch`, default `develop`) rather than whatever the main checkout happens to be parked on. The Explorer's root folder is labelled by its branch, like the sidebar, instead of by the directory name.
- **AI agents per worktree** — launch Claude Code, Codex CLI or opencode (pluggable providers); multiple agent and shell sessions per worktree, each tracked separately. The card's split button starts your primary agent and its chevron opens an in-sidebar menu for the others, dimming any whose command is not on `PATH`.
- **tmux-backed sessions** that survive VS Code window reloads and reconnect automatically. If tmux is missing, the Worktrees view says so and installs it in one click.
- **New agent panel** — a full editor page, not a modal squeezed into the sidebar: title, base branch, and room to write the task. It opens on its own when a repository window has no tabs open. Creating a worktree selects it the way clicking its card would, its terminal appears at once so the agent's boot is watched rather than waited out, and the first prompt is pasted whole and submitted only once the agent's own `SessionStart` hook says it is listening — never through the shell, so `${...}` and backticks survive intact.
- **State at a glance** — per-session status with live task titles, a sidebar attention badge, and an optional native notification when an agent needs you.
- **Active-worktree scoping** for text search, Quick Open, and breakpoints — plus editor tabs and terminals via the opt-in `stack.focusMode`.
- **Instant worktree switching** — switching reveals the target worktree's agent terminal without tearing down tabs or terminals, so there is no flicker and VS Code keeps your tab order. `stack.focusMode` restores the clean-slate behaviour (close and reopen everything) for those who prefer it.
- **Diff review panel** comparing against the branch the worktree was actually cut from, with per-line comments fed straight back to the agent.
- **Screenshots go where you drop them.** Drop an image onto an agent's terminal and Stack hands it to that agent — the one you dropped on, not merely the active one — leaving images you opened on purpose alone; a toast offers "Open instead". `Cmd+Alt+V` in the agent's terminal attaches the latest screenshot from your screenshots folder.
- **Settings panel** behind the gear beside **+**: one editor page for everything Stack can be told. The project half (worktree folder, base branch, setup/teardown scripts, a Docker stack per worktree, a debugger per worktree) saves to `.stack/config.json`; the personal half (primary agent and its commands, notifications, focus mode, search scoping) saves to your own VS Code settings. It prefills from the repository — compose files and the `${HTTP_PORT}`-style variables inside them, the language stack for a debugger preset (Node, PHP/Xdebug, Python, Go) — offers native file pickers, writes starter scripts on request, reads the saved file back through the same validator the extension uses, and says when your own settings.json overrides the file for this repo.
- **Per-worktree debugging** — a `launch.json` generated per worktree on a unique debug port, from a template you control; any debugger VS Code supports, Node by default.
- **Per-worktree Docker** orchestration with auto-generated, collision-free ports (opt-in). Ports are validated by binding them, so a slot is only handed out when the whole block is actually free on the machine, and checked again just before a stack comes up; a worktree whose port was taken in the meantime moves to a free slot instead of failing inside `docker compose`. Each card lists the ports it owns, clickable to open `http://localhost:<port>`.
- **Per-worktree setup/teardown scripts** with `STACK_*` environment variables.
- **Committable repo configuration** — `.stack/config.json` carries the settings that describe the project so a teammate who clones the repo inherits a working setup. Precedence is your own explicit setting, then the repo file, then the shipped default; per-user settings such as which agent you prefer are refused rather than silently applied.
- **Drift against the base branch** — each card shows how far its branch has fallen behind the one it was cut from (`origin/develop ↓12`), a different question from ahead/behind against your own upstream. Stack never fetches on its own; it names which ref it compared against and fetches only when you click the row.
- **Renameable sessions** and **shell sessions that say what they are running** (`npm`, `vim`, `psql`), read from tmux.
- **A Get started walkthrough** (opens on install; later under Help → Welcome, or `Stack: Getting Started`), and a one-time offer, per repository, to set up Docker and debugging when Stack first sees a compose file or a PHP stack.
